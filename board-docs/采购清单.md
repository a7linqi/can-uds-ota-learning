## 一句话结论

**只需要买 3 样东西，合计约 100–350 元：**

1. **USB-CAN 适配器**（核心，100–300 元）
2. **杜邦线 / 双绞线**（几元）
3. **USB 数据线**（几元，注意必须是数据线不是充电线）

**CAN 收发器不用买** —— 板子上已经焊好了。

## 二、必须买

### 1. USB-CAN 适配器 —— 核心，100–300 元

**为什么必须买**：电脑没有 CAN 接口。项目 PC 端工具用 `python-can` 发帧，没有适配器只能跑模拟模式，无法做真实升级实验。

#### 硬性要求（缺一不可）

| 要求 | 说明 |
|---|---|
| **必须被 `python-can` 支持** | 否则只能手点厂商软件，跑不了项目的自动化测试 |
| 支持经典 CAN 2.0A/B | 项目用标准帧，500 kbit/s |
| 速率覆盖 500 kbit/s | 最低要求 |
| **120 Ω 终端电阻可开关** | 板载已有一个，适配器这个要能控制，避免叠加出错 |
| 接线端子 | 4 针端子（CANH / CANL / GND / 5V）优于裸排针 |

#### python-can 支持的接口类型

| 接口 | 代表产品 | 支持情况 |
|---|---|---|
| **`gs_usb`**（candleLight 固件） | **CANable 2.0**、DSD TECH **SH-C30A / SH-C30G** | ✅ 原生支持，Windows 免驱（WinUSB） |
| `slcan`（串口协议） | 多数开源适配器 | ✅ 支持 |
| `pcan` | PEAK PCAN-USB | ✅ 支持，但千元级 |
| `usb2can` | 8devices | ✅ 支持 |
| **厂商私有协议** | 几十块的"USB-CAN 分析仪" | ❌ **通常不支持** |

#### 推荐方案

**首选：基于 CANable 开源方案的适配器**

| 型号 | 特点 | 参考价 |
|---|---|---|
| **DSD TECH SH-C30A** | CANable 复刻，gs_usb 固件，120 Ω 开关，非隔离 | 约 100–150 元 |
| **DSD TECH SH-C30G** | 同上 + **2.5 kV 电气隔离**，保护电脑 | 约 150–250 元 |
| **CANable 2.0**（原版） | 开源硬件，美国产，支持 CAN FD | 约 200–300 元 + 运费 |

**建议买隔离版（SH-C30G 一类）**：多花几十块，避免 CAN 侧故障打穿电脑 USB。做车载/工业实验，隔离是标准做法。

**次选：PEAK PCAN-USB**（约 1000 元+）
工业级、驱动最稳、`pcan` 接口成熟。如果预算宽裕或以后要做专业 CAN 工作，一次到位。**但对你现在的需求属于过度配置。**

#### 不要买

| 类型 | 为什么 |
|---|---|
| 只有厂商私有软件的"USB-CAN 分析仪"（几十元） | python-can 用不了，只能手点软件，无法跑项目测试 |
| CAN FD 专用高价型号 | 项目只用经典 CAN，多花钱无收益 |
| 无终端电阻开关的裸板 | 需自己外接电阻，接线更乱 |

---

### 2. 杜邦线 / 双绞线 —— 几元

| 项 | 要求 |
|---|---|
| 数量 | 至少 3 根（CANH / CANL / GND） |
| 类型 | 母对母或公对母，看 USB-CAN 端子类型 |
| **建议用双绞线** | CANH 和 CANL 绞在一起，抗干扰明显更好 |
| 长度 | 30–50 cm 足够（实验台短距离） |

**接线顺序**（务必确认，接反不通信）：

```
USB-CAN                探索者板
CANH  ────────────────  CANH
CANL  ────────────────  CANL
GND   ────────────────  GND      ← 必须共地，否则误码率高
```

终端电阻：**总线两端各一个 120 Ω**。板载已有一个，所以 USB-CAN 那个要**打开**（只接这两个节点时）。

断电用万用表测 CANH–CANL，应约 **60 Ω**（两个 120 Ω 并联）；如果是 120 Ω，说明只有一端有终端，需要打开另一端。

---

### 3. USB 数据线 —— 几元

**用途**：接板子的 `USB_232` 口（板载 CH340），看串口日志。

| 项 | 注意 |
|---|---|
| **必须是数据线** | 很多廉价线只有电源针脚（充电线），插上电脑不认设备 |
| 接口类型 | 探索者 V3 的 `USB_232` 口，购买前对照实物确认是 Mini-USB 还是 Micro-USB |
| 长度 | 1 m 左右 |

**为什么重要**：板上 CH340 至今**未被电脑识别**（主机枚举只有蓝牙串口）。没有串口，就看不了固件运行时打印，只能靠 SWD 读 RAM——能用但很别扭。

## 四、采购陷阱（这几条能省钱省时间）

| 陷阱 | 后果 | 怎么避 |
|---|---|---|
| 买了私有协议的廉价分析仪 | python-can 用不了，白买 | 商品页必须出现 `python-can` / `socketcan` / `gs_usb` / `slcan` 字样 |
| 买了充电线当数据线 | CH340 识别不出来 | 买"数据线"，或直接用手机原装线试 |
| 忽略终端电阻 | 通信不稳定、误码 | 选带 120 Ω 开关的适配器 |
| CANH/CANL 接反 | 完全不通，且可能损坏收发器 | 接线前对照丝印，先断电接线 |
| 忘记共地 | 误码率高、偶发失败 | 三根线里 GND 必须接 |
| 只靠 ST-Link 供电 | 烧录成功但板子不运行 | 单独 USB/DC 供电 |

## 五、到货验收（3 步确认能用）

```
第 1 步：插上电脑，看设备管理器
  └─ CANable/gs_usb 类型应直接识别，无需装驱动
     若显示未知设备 → 固件/驱动问题，先解决再往下

第 2 步：python-can 能否打开
  python -c "import can; bus=can.Bus(interface='gs_usb', channel=0, bitrate=500000); print('OK'); bus.shutdown()"
  └─ 打印 OK 说明接口通了

第 3 步：双节点通信
  └─ 接上板子，跑项目的 CAN 只读诊断，看能否收到 0x7E8 响应
```

**任何一步失败，先别怀疑板子** —— 大概率是适配器固件/接口类型选错，先确认 `interface=` 参数对不对。

## 七、不买也能继续做的事（所以不急）

买了才好，但**不阻塞当前工作**：

| 当前任务 | 是否需要 USB-CAN |
|---|---|
| NOR 全片只读备份（进行中） | ❌ 不需要 |
| NOR 写入驱动开发与验证 | ❌ 不需要（模型 + 板载 NOR 即可） |
| Boot/App 集成、目标构建 | ❌ 不需要 |
| 内部 CAN 静默回环 | ❌ 已用内部回环完成（stage=3 / passed=16） |
| **真实升级（PC → CAN → 板子）** | ✅ **需要** |
| **物理总线收发验证** | ✅ **需要** |

**结论**：USB-CAN 是"真实升级实验"的前置硬件。NOR 备份和写入驱动开发都不依赖它，可以并行推进。**建议现在下单，等它到货时，NOR 侧的工作也差不多做完了。**
