# 常用命令（STM32CubeProgrammer CLI）

> CLI 路径：`D:\Keil\CubProgram\bin\STM32_Programmer_CLI.exe`（本机 v2.23.0）
> 以下命令全部在本板（ST-Link V2，SN `I`）上实测有效。

---

## 一、连接与环境检查

```powershell
$cli = "D:\Keil\CubProgram\bin\STM32_Programmer_CLI.exe"

# 连接并显示芯片信息（Device ID / NVM size / 电压等）
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000

# 只读探测（不影响 Flash）
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 -coreReg PC
```

**关键参数**：

| 参数 | 说明 |
|---|---|
| `index=0` | 用第 0 个探针（**推荐**，`sn=I` 会报 `Wrong connect parameter`）|
| `mode=HOTPLUG` | 热插拔模式，不需要先复位 |
| `freq=1000` | SWD 频率 1 MHz |

---

## 二、烧录固件

```powershell
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 `
       -d "固件.bin" 0x08000000 -v -rst
```

| 参数 | 作用 |
|---|---|
| `-d <file> <addr>` | 下载到指定地址 |
| `-v` | 下载后校验 |
| `-rst` | 完成后复位 |

**注意**：会擦除对应扇区（这里是 sector 0）。

---

## 三、读内存

```powershell
# 读 32 字节（★ 第二个参数是字节数，不是字数！）
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 -r32 0x20000058 32

# 读 8 字节
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 -r32 0x08000000 8
```

**坑**：`-r32 <addr> <N>` 的 `N` 是**字节数**。写 `8` 只会读 2 个 32 位字。

### 导出内存到文件（读结构体最可靠）

```powershell
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 `
       -u 0x20000058 0x20 "out.bin"
```

`-u <addr> <size> <file>`，`size` 也是字节数。

---

## 四、读写核心寄存器

```powershell
# 读 PC / MSP / LR
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 -coreReg PC MSP LR

# 写寄存器（注意是 "寄存器=值" 的形式）
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 -coreReg MSP=0x20020000

# 读全部寄存器
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 -regdump
```

---

## 五、强制运行 Flash 固件（BOOT0 异常时应急）

当 BOOT0 被拉高、芯片停在系统 Bootloader 时，可以手动设 SPI + PC 强跳：

```powershell
# 1. 从 ELF 取 Reset_Handler 地址（用 nm）
$nm = "D:\Project\Can\toolchain\xpack-arm-none-eabi-gcc-15.2.1-1.1\bin\arm-none-eabi-nm.exe"
$reset = & $nm firmware.elf | Select-String " Reset_Handler" | ForEach-Object { ($_ -split '\s+')[0] }

# 2. PC 必须 +1（Thumb 位），否则会进 Default_Handler 死循环
$pc = "0x" + ([Convert]::ToInt32($reset, 16) + 1).ToString("X8")

# 3. 设 MSP + PC 并运行
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 `
       -coreReg MSP=0x20020000 -coreReg PC=$pc -run
```

**限制**：每次 CLI 连接都会复位芯片，固件无法长时间连续运行，**不适合需要持续执行的任务**（如 NOR 全片备份）。

## 六、复位

```powershell
# 软件复位（不拉低 NRST，LCD 不会被复位）
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 -rst

# 硬件复位（拉低 NRST，LCD 也会复位）
& $cli -c port=SWD index=0 mode=HOTPLUG freq=1000 -hardRst
```

## 七、常用地址速查

| 用途 | 地址 | 说明 |
|---|---|---|
| 内部 Flash 起始 | `0x08000000` | 向量表 / Bootloader |
| 内部 Flash 结束 | `0x080FFFFF` | 1 MiB 上限 |
| SRAM 起始 | `0x20000000` | 128 KiB |
| SRAM 结束 | `0x2001FFFF` | |
| CCM RAM | `0x10000000` | 64 KiB，仅 CPU 可访问 |
| DBGMCU_IDCODE | `0xE0042000` | Device ID（`0x413`）|
| Flash 容量寄存器 | `0x1FFF7A22` | `0x0400` = 1024 KiB |
| FSMC BCR4 | `0xA000000C` | Bank1 NE4 控制寄存器 |
| FSMC BTR4 | `0xA0000010` | Bank1 NE4 时序寄存器 |
| GPIOF ODR | `0x40021414` | LED（PF9/PF10）|
| SCB->VTOR | `0xE000ED08` | 向量表偏移 |
| SCB->CFSR | `0xE000ED28` | 故障状态（0 = 无故障）|

## 八、故障排查速查

| 现象 | 优先检查 |
|---|---|
| `No debug probe detected` | USB 线是否插好、设备管理器是否有 `STM32 STLink` |
| 烧录成功但程序不跑 | **BOOT0 是否为 0**（读 PC 看是否在 `0x1FFFxxxx`）|
| 读内存全是 0 | 目标地址是否正确、芯片是否在运行 |
| 读到的值一直不变 | CLI 每次连接都复位，固件可能还没执行到写 RAM |
| `Wrong parameter: sn=I` | 改用 `index=0` |
| `-coreReg MSP 0x...` 报错 | 正确写法是 `-coreReg MSP=0x...` |
| 程序进 `Default_Handler` | 检查跳转地址 bit0 是否为 1（Thumb）|

---

## 九、踩过的坑（血泪）

1. **`-r32` 第二个参数是字节数**，不是 32 位字数。写在文档里，别再踩。
2. **写寄存器必须用 `=`**：`-coreReg MSP=0x20020000`，不是空格。
3. **`sn=I` 会报 `Wrong connect parameter: sn=i`**，用 `index=0` 代替。
4. **每次 CLI 连接都执行 Software reset**，所以无法跨命令维持芯片运行状态。
5. **`HAL_SRAM_Init()` 返回 OK 不代表硬件配好了** —— 时钟没开时寄存器写入全丢，但函数不报错。
