# LCD 验证报告

**日期**：2026-11-03 19:20 – 20:03（Asia/Shanghai）
**目标**：确认板载 3.5 寸 TFTLCD 是否完好
**结论**：**屏幕完好，驱动完全打通，可实现全屏填充颜色**

## 一、验证目标与方法

用户要求"先验证一下屏幕的好坏"。工程里没有 LCD 驱动，因此从零写了一个独立探测固件：

- 驱动背光（验证背光模组与供电）
- 配置 FSMC 16 位 8080 并口（验证总线）
- 读驱动 IC 的 ID（验证 IC 是否响应）
- 填充 GRAM 并打开显示（验证完整数据通路）

代码放在独立目录 `stages/lcd-test/`，**不污染** `ota-core/` 和 `stages/board-lab/` 的构建快照。

## 三、关键数据

### 探针结构（`g_lcd_probe`，32 字节）

| 字段 | 值 | 含义 |
|---|---|---|
| `magic` | `0x5044434C` | 'LCDP'，固件运行 |
| `id_04` | `0x00008000` | 读 `0x04` 命令的响应 |
| `id_d3` | `0x00000000` | 读 `0xD3` 无响应 |
| **`id_d4`** | **`0x00015310`** | **拆为 01 / 53 / 10 → `0x5310` = NT35310** |
| `sram_init` | `0` | `HAL_SRAM_Init()` 返回 OK |
| `backlight` | `1` | PB15 已驱动 |
| `hclk_hz` | `16000000` | 16 MHz（HSI，未配 HSE） |
| `status` | 递增 | 循环心跳，固件存活 |

### FSMC 寄存器

| 寄存器 | 值 | 含义 |
|---|---|---|
| `BCR4`（修复前） | `0x00000000` | bank 未使能，配置全丢 |
| `BCR4`（修复后） | `0x0FFFFFFF` | 16 位 SRAM 模式，写使能，bank 使能 |

### 背光

| 项 | 值 |
|---|---|
| 引脚 | **PB15**（不是资料里说的 PB0） |
| 极性 | 高电平点亮 |
| 现象 | 拉高后屏幕整片发白 |

## 五、踩到的五个坑（按发现顺序）

1. **HAL 总头文件不含 SRAM 模块** —— 需要 `#define HAL_SRAM_MODULE_ENABLED` 并 include `stm32f4xx_hal_sram.h`。
2. **BOOT0 导致芯片不从 Flash 启动** —— `PC = 0x1FFF3xxx`，固件根本不运行。
3. **Cortex-M 跳转地址 bit0 必须为 1** —— 写偶数地址会进 `Default_Handler`。
4. **FSMC 时钟未使能**（最隐蔽）—— `HAL_SRAM_Init()` 返回 OK 但 `BCR4 = 0`，写入全丢。根因是 `HAL_SRAM_MspInit()` 是空弱函数。
5. **`0x01` 软复位清屏 + 缺电源配置** —— 导致"刚刚有、现在没了"和"只有背光没有图像"。
