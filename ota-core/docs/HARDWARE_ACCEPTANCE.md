# 板子到货后的验收入口

正点原子探索者 F407 的版本选择和官方资料见 [资料核对说明](ATK_EXPLORER_F407.md)，实物信息记录在 [板卡接收记录](BOARD_RECEIPT.md)。

2026-11-02 已完成首次实物 SWD 识别：系列 ID 0x413、内部 Flash 1 MiB，匹配 ZG 容量配置，记录见 [板卡接收记录](BOARD_RECEIPT.md)。截至 2026-11-05，只读镜像、串口台架、签名安装/连续升级和 TRIAL 回滚已上板；真实 CAN、物理 VDD 断电和硬件 IWDG 仍未执行。下一步按本表完成剩余实机验收；模型测试和主机注入次数分别记录。

| 阶段 | 操作 | 通过条件/记录 |
|---|---|---|
| 1. 芯片与工程 | 核对实物完整丝印，调试器读取 Device ID 和 Flash 容量 | F407 的 ID 不能单独证明具体容量；ZG/ZE 配置必须匹配实际读数 |
| 2. 最小 BSP | 根据实物原理图配置时钟、毫秒计时和 LED；验证启动/复位 | 提交实际引脚与时钟表，保留最小可运行工程；默认未配置 BSP 不能直接当固件使用 |
| 3. 只读 CAN | 门控全为 0，先回环，再以 USB-CAN 读取 F186/F195/VIN | 标准请求 7E0/应答 7E8、波特率与终端匹配；F195 是演示 Bootloader 字符串，不是 App 版本 |
| 4. 存储探测 | 核对 EEPROM 地址/页长、NOR 型号/JEDEC/保护位 | 单独确认页边界、时限和服务点；当前 NOR 配置只支持人工核对的 W25Q128JV-IQ/JQ |
| 5. 保存原内容 | 首次擦写前导出 EEPROM 和实际 NOR 原内容 | 保存校验和；开发板可能已有字库/演示资源，确认前 2 MiB 可分配给本工程 |
| 6. 手动升级 | 使用真正链接于 08010000 的 App BIN，先不启用看门狗 | 首装 V1、自检确认、升 V2、未确认后手动复位恢复 V1；读取 DID 0200 和可见 App 行为 |
| 7. 长操作时序 | 采集 0x78、最终应答、SPI WIP 与服务点间隔 | 测量 P2/P2*、最长 BSP 调用和整体请求时间；按实测选择客户端总期限 |
| 8. 看门狗 | 测量 LSI/实际超时与最长内部擦除，再单独启用门控 | App 死循环、健康失败、确认写失败后实际自动复位；确认合法安装不会被误复位 |
| 9. 断电回归 | 下载、提交、备份、安装、试运行、回滚分阶段断电 | 实测 MCU VDD 已真正断开；重启后只启动完整已验证镜像或留在诊断入口 |

内部镜像和 EEPROM 已有双副本事务保护，但存储内容备份是保留开发板原资源的措施，两者用途不同。不要盲目擦整颗 NOR；适配端口只允许工程已分配的前 2 MiB。

## 需要先补的实板内容

- 实际 CubeMX/Keil 工程、引脚与中断绑定、目标完整链接及 map 中 64 KiB Bootloader 占用检查。
- 真正可执行的两个 App 版本及其自检逻辑。测试中的向量+填充 payload 不能下载进 MCU。
- 分阶段定点断电的 GPIO/UART 标记与继电器控制绑定。当前软件有主机故障注入，尚未提供板上阶段触发引脚。
- 明确整板供电路径，排查调试器/USB 等路径导致的反向供电；切继电器命令不能直接算作一次有效断电。

## 记录口径

使用 `evidence/hardware-results-template.csv` 的空表头记录实际测试。每次保留包 SHA256、镜像版本/长度、CAN 记录、断电位置、复位原因、升级状态及可见 App 行为。未知数据留空，不填成 0。

刷写耗时要事先定义起止点，例如从 0x34 请求到 App 健康确认；下载、安装、首次启动确认可以分别计时。总线负载需要来自采集/分析工具的实测。断电次数只统计有证据证明 VDD 断开的循环，不能把 429 个主机模型场景写成 429 次真机断电。

在上述完成前，简历可写 C 核心、虚拟 CAN 台架、UART 台架、恢复状态机，以及已在 UART 台架实物走通的签名安装/回滚；不要写真机速度、物理断电通过率、真实 CAN、生产级安全启动或完整量产 OTA。
