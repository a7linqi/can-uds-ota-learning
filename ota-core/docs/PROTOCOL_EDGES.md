# 协议边界回归

`tests/test_protocol_edges.c` 使用可控 CAN 发送失败与虚拟毫秒时钟，补充正常刷写之外的边界。加入这些断言后，修复前出现 39 个失败断言；修复后全部通过。失败断言数不是独立缺陷数量，其中包含同一问题在不同参数下的验证。

| 边界 | 修复后的行为 |
|---|---|
| SF、FF 或 CF 交给 CAN 驱动失败 | 记录发送错误，结束当前发送状态，允许发起新传输 |
| 接收端发 FC 失败 | 放弃此次多帧接收，记录错误 |
| 连续 WAIT | 工程策略最多接受 3 次，第 4 次终止传输 |
| 正在发 CF 时收到非预期 FC | 忽略，不改动正在使用的块长/STmin |
| STmin `F1..F9` | 表示 100..900 us；本实现只有毫秒时钟，向上取整为 1 ms，不按 127 ms 处理 |
| 保留 STmin 编码 | 当前实现拒绝并终止该传输；属于本工程的严格子集策略 |
| 数值相同的扩展帧 ID | 不被当作标准帧链路接收 |
| 消息尚未被上层读取 | 保留第一条完整消息，不被随后数据覆盖 |
| 首帧长度超出缓冲区 | 发 FC Overflow，记录溢出，不进入接收态 |
| `uint32_t` 毫秒计数回绕 | N_BS/N_CR、S3 和演示 Seed/Key 的 10 秒锁定均按无符号时间差判断 |

锁定状态在 RAM 中，复位后不保留；Seed/Key 仍是公开演示算法。这次修复保证计时和状态机行为，不增加密码学安全性。

每次启动新的有效收发会清理对应历史错误。CAN 回调返回 0 只代表驱动或其软件队列接受了帧；是否已上总线需要另外检查硬件发送完成。复位路径已同时等待 ISO-TP、软件队列和硬件邮箱空闲。

这些检查没有验证总线仲裁、Bus-Off 恢复、CAN FD、扩展/混合寻址格式或完整 ISO 一致性。支持的是经典 CAN、正常寻址和 12 位长度的工程子集。

参考：[Linux 内核 ISO-TP 文档](https://docs.kernel.org/networking/iso15765-2.html)，其中列出了 BS、STmin、WAIT 上限参数及错误类别。本实现没有引入 Linux 代码，也不要求目标 MCU 运行 Linux。
